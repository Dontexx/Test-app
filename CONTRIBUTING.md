# Правила участі у розробці (CONTRIBUTING)

Вітаємо! Дякуємо, що вирішили допомогти з розвитком конвертера валют. Будь ласка, дотримуйтесь наведених нижче правил.

## Як повідомити про помилку або запропонувати функцію

Використовуйте GitHub Issues:

- **Bug Report** – обирайте шаблон `Bug report` і детально описуйте кроки відтворення.
- **Feature Request** – обирайте шаблон `Feature request` та аргументуйте пропозицію.

## Стиль оформлення комітів

Використовуйте префікси:

- `feat:` – нова функціональність
- `fix:` – виправлення помилки
- `docs:` – зміни документації
- `test:` – додавання або зміна тестів
- `refactor:` – рефакторинг

**Приклад повідомлення коміту:**  
`feat: add export to CSV for conversion history`

## Робота з гілками

- Основна гілка – `main`. Усі зміни мають надходити через pull request.
- Для нових функцій створюйте гілку з назви: `feature/короткий-опис`
- Для виправлень: `bugfix/опис-помилки` або `fix/номер-issue`

## Процес створення Pull Request

1. Створіть гілку від актуальної `main`.
2. Внесіть зміни, дотримуючись стилю коду (PEP 8).
3. Додайте тести, якщо це логічне розширення функціоналу.
4. Запустіть тести локально: `pytest` – всі тести мають проходити.
5. Створіть pull request у GitHub, обов'язково опишіть, що було зроблено, і прив'яжіть номер issue (якщо є).
6. Після рев'ю та схвалення PR буде злито.

## Код-стайл

- Дотримуйтесь PEP 8.
- Використовуйте зрозумілі назви змінних та функцій.
- Додавайте коментарі до складних місць.

## Ліцензія

Вносячи зміни, ви погоджуєтесь, що вони будуть поширюватись під тією ж ліцензією, що й проєкт (MIT).
